# 原生 EHT 热点模块生命周期与构建

日期：2026-10-25。承接原生 EHT 热点频段与带宽入口，把一次性 runner 整理成显式 KernelSU action 控制器。本文是开发和离线检查点；没有在手机启动最终热点，也没有重复无线窗口。

## 实现

- 新增 `modules/mt6639-hotspot`，默认 `ENABLE_AT_BOOT=0`。只有 KernelSU 模块“操作”按钮会 toggle start/stop；开机 service 默认只记录不启动。
- `bin/control.sh` 仅接受 `/data/adb/modules/mt6639-hotspot` 的 root/`u:r:ksu:s0` action；有状态启动要求 SELinux Enforcing。recover/guardian 在 Enforcing 或 Permissive 都可执行，保证安全姿态变化不会卡住清理。
- 会话绑定当前 boot。runner 与 guardian 都记录 PID 和 `/proc/PID/stat` 第22字段开始时间；控制器同时校验进程命令行、任务路径、starttime 和 boot，不按“PID 存在”或旧 `recovery.rc` 晋级。
- `status`/active 每次用本任务 `hostapd_cli` 重新读取 `state=ENABLED`，覆盖旧状态后再用规范 profile 核对频率、HE/EHT 宽度、中心索引和副信道；同时要求 runner、guardian、native hostapd、`mtap0 - TetheredState` 全部成立。启动时留在磁盘里的旧 `status.active` 不能满足 active。
- `stop` 写本任务 `cleanup.request`，同时等待 runner/guardian 结束。若 guardian 已消失但 `recovery.rc` 缺失，同 boot 且任务归属通过时调用同一 runner 的受控 `recover`，再核对 `recovery.rc=0`、mtap0 消失和 Tethering 退出。跨 boot 或任何归属不确定态返回78并保留 authority，不用旧结果清空。
- runner 成功启动后不再无条件自清理。默认 hold 90秒，模块 action 默认 86400秒；stop 或模块 `disable/remove` 触发恢复。只有 action 失败、进程异常退出或显式 stop 才立即写 cleanup。
- 私有 `ap.key`、`reconnect.key` 位于 `/data/adb/mt6639-hotspot/private/`，要求 root所属0700目录/0600文件；源码、ZIP 和测试均不包含真实口令。
- `tools/build_hotspot_module.sh` 从新输出构建 ZIP，固定 hostapd `15023e...`、hostapd_cli `2da7d4...`、NativeTether DEX `6feb2b...`、SoftAP profile DEX `1a82a8...`、profile helper `c7f932...` 和 twt recovery 输入，排除 `local/`、`outputs/`、日志及密钥。

## 构建与检查

最终源码构建命令：

```sh
sh tools/build_hotspot_module.sh \
  outputs/hostapd-standalone-20261025-1/bin \
  outputs/native-tether-build-20261025-1/classes.dex \
  outputs/softap-profile-build-20261025-3/classes.dex \
  outputs/hotspot-module-20261025-6/mt6639-hotspot-v0.1.0.zip
```

产物 5,306,279字节，SHA256 `9d8e3a2d1c9116e50e890f2ab668f73681bbdee0e75a8f23474daee3463e5f02`。ZIP 增加 `customize.sh`，安装器会把 action/runner/hostapd 等脚本恢复为0755；`SHA256SUMS` 覆盖全部 `bin/` 文件，且没有 `ap.key`、`reconnect.key`、`local/` 或 `outputs/`。

离线验证：

- `/usr/bin/python3 -m unittest discover -s tests -p test_hotspot_module.py -v`：4项通过，覆盖语法/默认关闭、runner hold 和模块禁用 guard、凭据扫描、固定哈希打包。
- `/usr/bin/python3 -m unittest discover -s tests -p test_native_ap_config.py -v`：6项通过。
- 相关 shell `sh -n` 和 `git diff --check` 通过。
- 两轮只读审查：第一轮指出成功自清理、真实口令、boot/PID归属和 guardian 孤儿问题；定点修复后第二轮继续指出 guardian 死亡误报 active、缺少主动 recover 和旧状态复用，均已修正；最终复核无新增直接阻塞。

KernelSU v3.3.1 管理器已能通过 `content://... application/zip` 导入该模块，安装日志完成 `Module installed successfully`。完整重启后模块位于 `/data/adb/modules/mt6639-hotspot`，其中最终 `control.sh` SHA256 `8b036561...dfd1`、`softap_native_once.sh` SHA256 `c53bfda8...9b64`，与源码和ZIP清单一致；旧目录备份保留在 `/data/adb/mt6639-hotspot/module-before-<BOOT_ID>`。设备实际发现解包后的 `action.sh` 为0644，已补入 `customize.sh` 自动修权限；当前活动目录经同一操作修复后为0755。

在 SELinux Permissive、缺少私有口令的当前窗口点击 KernelSU “执行”，控制器记录 `REJECT enforcing_required`，未创建 session、`mtap0` 或 Tethering 上游，STA 仍连接 LabNet-5G。该结果证明 action 已真实执行且 fail-closed；它不代表热点启动通过。

## 边界

当前只接受 6GHz 20/40/80/160/320MHz profile，固定 LabNet-6G 上游；5GHz AP 与固定6GHz STA的信道协调冲突仍未解决。系统热点UI、IHostapd Binder、IPv6/offload、外部客户端、宽带宽业务、异常矩阵和长稳仍归F07/F10。

文档已列的原生 AP netdev 消失、进程在 starttime/PID 记录前死亡、`TETHERING_VIRTUAL` 单例归属等边界继续有效。本模块不会猜测和停止其它任务的热点；无法证明归属时保留 authority。最终发布前必须在 Enforcing 下完成一次 action start/status/stop、模块 disable 恢复、跨 boot 整理和失败/取消测试。

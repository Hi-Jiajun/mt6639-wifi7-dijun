# F03 DUP 三点取证方案

日期：2026-10-28。工具：`tools/dup_capture.py`，Python 标准库，复用现有 `compare_icmp_paths.py` / `summarize_icmp_pcap.py` 的经典 pcap 解析器。

本轮仅完成实现与离线自测，**没有执行真机采样**。禁止 AP monitor / trace 的约束保持不变。脚本默认 dry-run；只有 `--execute` 会访问手机和 SSH 主机。它只发送低流量 ICMP、抓包、读取计数，不重启、不改关联和无线配置、不安装工具。停止时只向本次启动的 tcpdump PID 发 SIGINT，不使用 pkill / killall。

## 三个观察点与证据上限

1. 手机 `wlan0`：`su -c /system/bin/tcpdump`，记录解封装后的 IPv4 ICMP 请求和回复，在本次独占的 `/data/local/tmp/f03-dup-<随机ID>/` 内写 `phone.pcap` 与 `tcpdump.log`；结束后 `adb pull` 拉取两者，再删除本次文件和空目录。手机 pcap 不再经 su stdout 流式传输；su/adb 的客户端输出另存 `phone-capture-client.log`，避免提示文本污染 pcap。拉取失败或无法确认捕获停止时保留远端目录，在 manifest 给出路径供恢复。
2. 有线目标 `.60`：`ssh root@198.51.100.60`，默认直接运行 tcpdump（`--wired-no-sudo`），在一张实际承载手机路由的网卡抓同一 ICMP 流。目标必须是这张网卡的本地 IPv4，禁止 `any` / `lo`。当前本窗口真机冒烟确认普通用户无抓包权限、该机无 sudo，root BatchMode 可用；因此默认改为 root 直连，不尝试安装 sudo 或修改权限。其它主机确有 sudo 时才显式用 `--wired-sudo`。
3. 手机 ping 应用日志：绑定 `wlan0`，逐 seq 记录正常回包、DUP 标记、RTT；默认 `-D` 带手机系统时间。如果系统 ping 不支持 `-D`，保留失败样本，下一次可加 `--no-ping-timestamps`；此时应用日志时间戳为 null，两个 pcap 仍有完整时间戳。

AP 是可选的辅助计数源，不是第四份 pcap。可用 `--ap-host`、`--ap-interface`、`--station-mac` 读取前后 `iw station get`、`hostapd_cli sta`、`bridge -s link show` 和 `ip -s link`。不会进入 monitor / trace，也不会扫描或修改 AP。AP SSH 用户必须已有所需读取权限；接口或工具不可用时保留 stderr，重试率标成 unknown。

**普通 wlan0 pcap 没有 802.11 Frame Control Retry 位和 Sequence Control，因此不能证明或排除空口重传。** 802.11 真重传应依据同发送方/接收方、TID、序号与分片号、Retry 位及时间邻近的空口 MPDU 识别；同一 MSDU 在不同 MPDU 中也可能需要更深解码。在本任务禁抓空口条件下，该项始终是 `unobservable_without_80211_headers`。AP `tx retries` 增量只能提供下行重传压力的相关性，不能把某个 ICMP DUP 指定为某个 802.11 retry；正常链路重传也通常会被接收端去重。

## 下一窗口直接执行

在仓库根目录执行，第一条只展示命令，不运行 adb / SSH，不创建输出目录：

```bash
/usr/bin/python3 tools/dup_capture.py --duration 60 --interval 0.2 \
  --out outputs/dup-capture-20261028-window01

/usr/bin/python3 tools/dup_capture.py --execute --duration 60 --interval 0.2 \
  --adb outputs/linux-adb-20261026/extracted/platform-tools/adb \
  --serial YOUR_SERIAL --wired-host root@198.51.100.60 --wired-no-sudo \
  --target 198.51.100.60 --out outputs/dup-capture-20261028-window01
```

建议先做 60 秒、200ms 间隔（300 请求，约 5 pps），若异常未出现，再换**全新目录**连续做 2–3 窗；不要增加并发 ping。手机 IPv4、`.60` 的具体网卡可自动只读发现；已知时可显式传 `--phone-ip 198.51.100.X --wired-interface ens18`（示例地址/接口必须替换为实际值）。执行前会验证手机地址和目标地址确实位于各自的指定接口上。输出目录已经存在时拒绝覆盖。

有已核实 AP SSH 地址、6GHz AP 接口及该关联的随机 STA MAC 时，在相同命令末尾添加：

```text
--ap-host root@198.51.100.242 --ap-interface <实际6GHz接口> --station-mac <AP所见手机MAC>
```

尖括号是待替换字段；不要原样复制。`--wired-no-sudo` 已为默认值，给出的执行命令显式写出它以便审计。如可执行文件不在 PATH，用 `--wired-tcpdump /实际路径/tcpdump`，参数只接受程序路径，不接受 `sudo tcpdump` 之类命令前缀。

两端 tcpdump 并发启动，就绪判定为**远端 tcpdump PID 存活、adb/SSH 客户端未退出、pcap 至少 24 字节头**；不需要已有首包，也不依赖 `listening on` 文本。手机通过 su 读取本次 pidfile、`kill -0`、`wc -c` 与日志尾部；有线侧查询远端 PID，并检查流式接收的本地 pcap 字节数。10 秒内不满足则不发业务，错误与 manifest 会逐点列出进程存活状态/PID、客户端退出码、pcap 字节数、远端日志尾部和客户端日志尾部。默认抓包 watchdog 为发送窗口 +30 秒，带 AP 计数时为 +60 秒。正常 ping 和快照结束后即向本次 PID 发 SIGINT，等 tcpdump 刷新并退出，再拉取手机文件；正常约 60 秒业务加少量启动/收尾时间，不必等满 watchdog。ping 最长等待窗口 +8 秒；掉线、提前退出或超时均保留已有文件并判为无效证据。远端 supervisor 自带有界停止，即使本地 adb / SSH 客户端掉线也不会永久抓包。

离线重算和自测：

```bash
/usr/bin/python3 tools/dup_capture.py --analyze outputs/dup-capture-20261028-window01
/usr/bin/python3 tools/dup_capture.py --selftest
```

也可把已有 `phone.pcap`、`wired.pcap`、`ping.txt` 及两个 `*-tcpdump.log` 放进独立目录，再 `--analyze <目录> --phone-ip <手机IPv4>`。没有 tcpdump 起止及零丢弃页脚时仍可列出观察结果，但质量门无效。多个 ICMP ID 并存时不自动猜业务；确认原业务 ID 后用 `--icmp-id <十进制ID>` 重算。该选择不能补回丢失的数据。

## 逐包关联与落点判据

以方向规范化后的手机地址/目标地址 + ICMP ID + seq + **完整 payload SHA256** 对齐，排除截断、分片和不匹配 payload。IP ID、每份包的 pcap 原始 epoch / UTC、点内相邻副本间隔、手机同一时钟内 RTT 都保留。跨设备时钟允许偏移；脚本不做跨主机时间相减，也不靠“两个时间接近”强行配包。若中间 NAT 改写 ICMP ID，本方法将产生关联缺口，需要单独识别 NAT 映射后再研究，不能当作实际丢包。

报告每个 group 的四个计数：手机请求 Pq、有线请求 Wq、有线回复 Wr、手机回复 Pr。`packet_count_differences` 给出 Wq−Pq、Wr−Wq、Pr−Wr 总差；`sequences` 保留所有序列；`duplicate_groups` 列出所有多副本组。`ping_dup_events` 每条保留原始 DUP 行、seq、应用时间戳、关联的 ID/payload；对应组有两端全部包的时间戳/IP ID，便于每个 DUP 回查。

| 观察 | 可以下的结论 | 下一步 |
| --- | --- | --- |
| Pq=1，Wq=1，Wr=1，Pr>1 | 手机 L3 观察点出现多个匹配回复；多副本增加位于有线观察点到手机观察点之间 | 对照 AP/STA 计数与 IP ID，复查桥接/FDB/有线拓扑、AP 转发、驱动接收去重；仅两端抓包不能定责 AP |
| Pq=1，Wq>1 | 请求在手机到有线观察点之间增加副本 | 检查 AP 桥接、有线环路/镜像、VM 网桥及驱动；同样不能凭此断言是空口重传 |
| Wq>1，Wr>1 | 回复可能是服务端对重复请求逐份回应 | 先追溯请求复制点，不能仅凭多回复责备 `.60` |
| Wq=1，Wr>1 | 多回复在有线观察点已可见 | 检查 `.60` 内核/虚拟网卡/虚拟交换机、捕获重复或本机响应路径；记录 IP ID 是否一致 |
| Pq>0，Wq=0 | 手机→有线之间存在请求**观察缺口** | 排查手机发出后路径及 `.60` 抓包覆盖/offload；不能直接宣布实际丢弃点 |
| Wq>0，Wr=0 | `.60` 看到请求但没看到匹配回复 | 查目标响应/过滤/限速、payload/ID 改写和抓包覆盖；不要自动调整 sysctl |
| Wr>0，Pr=0 | 有线→手机之间存在回复观察缺口 | 对照 AP 计数、回程路径和手机接收栈；不等价于 AP 丢包 |
| Pr>0，ping 没有该 seq；或 ping DUP 而 Pr≤1 | 手机捕获点到应用日志之间不一致，或会话/捕获覆盖问题 | 核对 ping 会话与日志、驱动/offload/协议栈分发，保留无损原始材料 |
| 仅 AP retries 高，L3/ping 均无重复 | 重传压力信号；未观察到 L3 DUP | 与同 STA 下行流量、信号、速率、tx failed 对照，不能映射单包重传 |

同一 seq 的副本具有相同 IP ID 可支持“同一 IP 数据报被复制”的假设，不是唯一证明；不同 IP ID 可支持“多次生成回复”等假设，也不能单独排除路由/重封装/ID wrap。报告不把普通 pcap 重复等同于 802.11 重传。

本方案对“AP 后段重复”的严格口径：若请求到 `.60` 前已经增加，或 `.60` 回包处已经重复，可以证明 L3 多副本在对应边界可见；只有手机看到新增回复时，候选范围是 `.60` 网卡到手机接收观察点的整个路径。**没有 AP 桥两侧同步 pcap，就不能把 AP 后段从 AP 内部/无线/手机驱动单独切出来。** 本方案不会为了缩小该范围突破 AP 禁抓包约束。

## 无效窗口与异常窗口

先判证据有效，再判异常；证据有效不代表链路通过：

- `quality.valid=false`：空 pcap、结构损坏/截断、orig>incl、缺 tcpdump listening / captured / dropped 页脚、kernel dropped 非零、pcap 数量与 captured 页脚不符、业务 ID 缺失/不唯一、ping 发送数量与手机唯一完整请求不符、ping 收到/重复汇总与逐行日志不符、进程非零/超时。原始结果仍保留；结构损坏的 pcap 会直接报解析错误。
- 有效但 `window.status=anomalous`：任意 DUP；ping loss **>5%**；AP 下行 `Δtx retries / Δtx packets ≥0.20`；手机 pcap RTT max ≥200ms；或有包/应用观察缺口。阈值为本轮排查筛选标准，不是厂商规范，也不是 F03 验收门槛；可用 `--loss-threshold` / `--retry-threshold` 调整。
- `no_observed_anomaly`：只说明此短窗没触发上述信号。AP 计数没采到或 Δtx packets=0 时 `ap_retry_coverage=unknown`，不能宣称重试率合格；不产生 F03 pass 结论。

AP retry 分母是 `iw` 逐 STA 的发送包数，分子是重传次数，不是“失败包概率”，可大于 1。负增量视为计数重置/重关联导致无效；样本覆盖此 STA 其它业务，含 SSH 快照前后的小量时间余量，只用于窗级相关性；不能代表 STA→AP 上行 retry。

每窗保存 `phone.pcap`、`wired.pcap`、`phone-tcpdump.log`、`phone-capture-client.log`、`wired-tcpdump.log`、`ping.txt`、`manifest.json`、`report.json`，可选 `ap-before.txt` / `ap-after.txt`。manifest 包含命令、开始/结束时间、退出码、原始文件字节数与 SHA256。退出码 0 表示采样/解析质量可用（异常也可以是 0）；2 表示调用或证据质量失败。只读诊断不会修改 candidate / host-test manifest。

## 离线验证边界

`--selftest` 构造经典 pcap，覆盖清洁序列、请求增加、副本在有线/手机侧分别增加、两方向观察缺口、payload 不匹配、每个 ping DUP 的 seq/时间戳关联、跨设备大时钟偏移、SLL 大端、tcpdump drops、retry 计数重置及截断文件，以及无首包/无 banner 的 24 字节头就绪、短头、进程死亡、客户端退出和详细错误诊断。合成测试只能验证工具逻辑；此次修复的 su 文件采样、adb pull、root SSH 抓包、真实驱动抓包点和 AP 命令权限仍需下一个独占真机窗口核实。本窗口此前已验证手机文件式 tcpdump 能生成 pcap；本代理没有访问设备。

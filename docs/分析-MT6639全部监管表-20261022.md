## 0. 结论摘要

1. **本轮在符号边界识别并解码了 7 个具体的 `ieee80211_regdomain` 规则表**：
   `default_regdom_ww`、`regdom_us`、`regdom_us01`、`regdom_cn`、`regdom_cz_nl`、`regdom_jp`、`regdom_tr`。
   除了按符号名匹配，另做了一次**不依赖名字的结构扫描**（符号大小 = `0x1c + N×0x60`、头部
   `n_reg_rules` 与 N 一致、每条频段三元组落在 2–8 GHz 且带宽合法），遍历 `.rodata` 与 `.data`
   的具名符号，命中数同样是这 7 个。不是逐字节全扫描，不能排除无符号、其它布局或动态对象。
2. **7 张表里只有 `default_regdom_ww` 含 6 GHz**：第 5 条 `5925–7145 MHz / 320 MHz`，flags=0。
   US / US01 / CN / CZ_NL / JP / TR 六张表**全部只覆盖 2.4 GHz 与 4.9–5.9 GHz**，没有任何 5925 MHz 以上的条目。
3. **NL 和 CZ 共用同一张表**：`my_regdom_nl` 与 `my_regdom_cz` 的重定位都指向 `regdom_cz_nl`。
   所以"按国家码可选"的索引项有 7 个，具体的表对象是 7 个（其中 6 个被国家码引用，1 个是世界默认）。
4. **索引是 4 字节国家码精确匹配 + NULL 结尾的指针数组**：`my_regdom[]` 只有 `US01/US/CN/NL/CZ/JP/TR` 七项，
   **WW 不在索引里**；查不到时走默认分支（返回码被置为 `0x3030` = `"00"`）。
5. **数据存在 ≠ 被选中 ≠ 允许 ≠ 射频可用**。本报告只完成第一层（表在镜像里存在且被精确解码）；
   第二层有静态证据（索引数组、重定位、查找函数）；开关函数返回1不是第三层“允许”的证据，
   第四层（固件能力、实际射频、当地法规）静态分析完全无法证明。

## 5. 索引、重定位与实际取表路径（静态证据）

### 5.1 `my_regdom` 是 16 字节索引项

```
struct my_regdom { u8 cc[4]; u32 pad; struct reg_domain *p; };
```

原始字节：`my_regdom_us01` = `"US01"`、`my_regdom_us` = `"US\0\0"`、`my_regdom_nl` = `"NL\0\0"` …
`+0x8` 处是 `R_AARCH64_ABS64` 重定位：

| 索引项 | 重定位目标 |
| --- | --- |
| `my_regdom_us01` (0xc3578) | `regdom_us01` |
| `my_regdom_us` (0xc3588) | `regdom_us` |
| `my_regdom_cn` (0xc3598) | `regdom_cn` |
| `my_regdom_nl` (0xc35a8) | **`regdom_cz_nl`** |
| `my_regdom_cz` (0xc35b8) | **`regdom_cz_nl`** |
| `my_regdom_jp` (0xc35c8) | `regdom_jp` |
| `my_regdom_tr` (0xc35d8) | `regdom_tr` |

指针数组本体在 `.data + 0x11ef0`（7 个 `R_AARCH64_ABS64`，指向上面 7 个索引项），后面紧跟 NULL 结束。
**结论：可选国家码 7 个，具体表对象 6 个（NL/CZ 共用），WW 不可被国家码命中。**

### 5.2 查找函数（`rlmDomainSearchRegdomainFromLocalDataBase`，0xb3500）

```
adrp x8,<ptr_array>; ldr x9,[x8]; cbz x9 -> return NULL
loop: ldrb w12,[x9]  / ldrb w13,[x0]   ; 逐字节比较 cc[0..3]
      ldr  x0,[x9,#8] ; ret            ; 命中返回索引项里的 reg_domain*
      add w8,#1; ldr x9,[base + idx*8]; cbz -> return NULL
```

即：**4 字节精确匹配 + NULL 结尾的 8 字节指针数组**，命中后取 `+0x8` 的 `reg_domain*`。
`"US"` 与 `"US01"` 是不同键（`"US\0\0"` vs `"US01"`），不存在前缀匹配。

### 5.3 更新函数（`rlmDomainUpdateRegdomainFromaLocalDataBaseByCountryCode`，0xb33d8）

把入参 `w0` 拆成 4 个字节逐一比较（与 5.2 同一数组、同一 NULL 终止），命中则 `ldr x0,[x8,#8]`。
**未命中分支**把返回码置成 `0x3030`（ASCII `"00"`）后走默认处理。
主线程核对重定位：`0xb34b0` 调用 `kalGetDefaultRegWW`，`0xb34b8` 调用
`kalApplyCustomRegulatory`；该函数最终在 `0xb34d0` 返回的是 `w20` 国家码，**不是规则指针**。

### 5.4 开关函数与默认表

- `rlmDomainIsUsingLocalRegDomainDataBase`（0xb37b8）：`bti c; mov w0,#1; ret` —— 无条件返回 1。
  这**只**证明"本地数据库开关被编译成启用"，不证明它是运行期唯一策略来源。
- `rlmDomainGetLocalDefaultRegd`（0xc2474，上一轮已解码）：单条尾调用到 `kalGetDefaultRegWW`（0x163cbc），
  后者在 0x163cc0/0x163cc4 用 `adrp/add` 引用 `default_regdom_ww`。

## 6. 另一种规则表示：厂商紧凑信道表

这两个对象**不是标准 `ieee80211_regdomain` 布局**，但不能据此否认其信道策略作用：

- `arSupportedRegDomains`：`.data+0xaea0`，大小 `0x770` = **34 × 0x38**；`arSupportedRegDomains_Passive`：`0x70` = **2 × 0x38**。
- `rlmDomainGetDomainInfo`（0xaf7a0）用 `umaddl x8, w3, #0x38, base` 以 0x38 步长取项；
  配置模式1下索引不大于 `0x21` 时直接取项；其它相关分支遍历34项，用 `entry+0` 的指针和
  `entry+8` 的计数，按u16数组比较**国家码**，不是比较频率。还有缓存和自定义域分支，不能省略。
- 可重定位ELF的指针槽为0不代表运行期才构造数据。`.rela.data` **有**这些槽的
  `R_AARCH64_ABS64` 重定位，例如 `.data+0xaea0 → .rodata+0xbec58`，
  `.data+0xb450 → .rodata+0xbee36`，Passive首项 `.data+0xb610 → .rodata+0xbee50`。
- 主线程已解码34组：每项 `+0xc` 起7个6字节子带。CN组5无band3；US/AS组26含
  `[131,3,4,1,59,0]` 与 `[136,3,4,2,1,0]`，枚举出60个6GHz信道号；其它多组也有6GHz。
- 当前真机只读查询的临时探针显示 `sku=0`、CN，确实走紧凑表路径。详见另一份禁用路径报告。

因此，**“标准US表无6GHz”与“厂商紧凑US组有6GHz”同时成立**；不辨调用分支就选表会得出错误结论。

## 7. 四层区分（本报告只完成第 1 层）

| 层 | 含义 | 本轮证据 | 状态 |
| --- | --- | --- | --- |
| ① 数据存在 | 镜像里有没有这张规则表、条目是什么 | 7个标准对象逐条解码，符号边界结构扫描 | **这些对象已证实，不宣称任意布局穷尽** |
| ② 被选中 | 运行期是否真按国家码取到这张表 | 索引数组、4 字节比较、重定位、未命中回落 `"00"` 分支 | **静态路径已证，运行期未观察** |
| ③ 被允许 | 通过 cfg80211/固件/SKU 过滤后是否放行 | 本报告的标准表静态分析不能证明 | **看最终信道flags和运行期分支，不能靠开关值** |
| ④ 射频可操作 | 真实能否起 6 GHz 关联/发射 | 无 | **未验证，静态分析无法证明** |

规则仍可能被固件能力（`fw6`/`cap4`）、SKU 配置、cfg80211 内建 regdb、或上层 nl80211 过滤再次裁剪。

## 8. 关于"选一个国家码"的边界说明

- 在**规则数据**这一层，原厂 `stock.ko` 已经自带 6 GHz 规则（WW 表第 5 条），
  不需要为了"拿到 6 GHz 规则数据"而替换驱动二进制。
- 但**把监管域切到某个国家码，不等于获得合法或功能上的 6 GHz 启用**：
  US/US01/CN/CZ_NL/JP/TR六张**标准表**没有6GHz，但当前使用的另一套紧凑表有多个国家组含6GHz。
  切换国家码的结果取决于实际调用分支及后续过滤，不能由这六张标准表单独推断。
- 因此不能说“本镜像没有国家表支持6GHz”，也不能把“存在数据”包装成“射频可用或合规”。
- 本报告不提供、也不会执行任何地区伪装（region spoofing）或强制发射（forced transmit）的补丁、命令或步骤。
  是否合法可用取决于设备实际所在地法规与型号认证，静态分析无法判定。

```bash
$OD -d --no-show-raw-insn --start-address=0x12bdd4 --stop-address=0x12be00 "$KO"
```

解码口径（读原始字节）：`.rodata` 文件偏移 = `0x1d840 + 符号值`，`n_reg_rules` 在 `+0x10`，
规则从 `+0x1c` 起、步长 `0x60`，`freq@0/4/8`、`power@0xc/0x10`、`flags@0x54`。
BTF 校验：`local/6g-test/inspect-btf.py local/6g-test/recovery-20261022-1456/vmlinux.btf ieee80211_regdomain ieee80211_reg_rule ieee80211_freq_range ieee80211_power_rule`。

符号边界结构扫描（不是“没有第8张表”的绝对证明）：遍历 `llvm-nm -S` 中所有 `R`/`D` 符号，
筛出 `size ≥ 0x7c` 且 `(size-0x1c) % 0x60 == 0` 的对象，要求头部 `n_reg_rules` 等于
`(size-0x1c)/0x60` 且每条 `start < end` 落在 2–8 GHz —— 在上述具名符号候选中命中这7个。

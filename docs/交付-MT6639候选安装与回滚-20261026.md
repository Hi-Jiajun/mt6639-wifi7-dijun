## 当前恢复前提

受控恢复记录已确认普通应用KSU通道、oneclick恢复分支及直接LAN状态/回滚可用；当前仍Permissive，因为Enforcing窗口内Zygisk/LSPosed状态超时且zn-daemon存在明确socket AVC，已回滚。先完成注入服务修复并获得稳定Enforcing证据，再进入以下无线升级窗口。

Linux ADB当前使用仓库内platform-tools/5037；Enforcing下kernel域adbd不能exec，USB forward也不独立。`tools/stage_6g_candidate.py`已增加显式`--ssh-command-json`：逐操作普通应用来源→system su→UID0/ksu，固定serial/boot，执行时逐操作检查双源Enforcing；ZIP走同一门禁stdin并核对远端SHA。21项宿主定点已通过，真实runner尚未运行。临时LAN实例此前已到期；跨Enforcing控制通道的历史证据不等于runner真机可用。SSH依赖Wi-Fi，checked restore可能断开连接；超时立即停为状态未确认，不自动重连/重放写操作。详见暂存工具与SSH边界。

## 安装顺序与授权边界

1. 在已批准的无线变更窗口，重新确认boot、fingerprint、KSU真实应用身份、双源Enforcing、注入服务和SIM；保存当前Wi-Fi、事务、Tethering及`mtap0`状态。
2. **先备份再恢复事务**：完整备份活动模块和运行目录，私有文件留在受保护位置；核对SHA及tar可列出活动module.prop，备份不合格即停止。
3. 从已验证的KSU通道执行旧6G事务checked restore，等待`state=restored`、`active_tx=none`和原厂cfg SHA一致；失败保留现场，不覆盖活动目录。
4. 按manifest固定的v0.2.13 ZIP/SHA经官方KSU安装，核对`modules_update`版本、versionCode15及SHA256SUMS。传输/域条件不满足或SSH状态未确认时停止，先只读核对现场，不重放安装。
5. 热点v0.2.9、UI0.2.6、Aware0.1.3可在各自前提齐全且另有部署授权后合并准备，以减少重启次数；并发APK仅作实验，scope默认不启用。**暂存成功后停止，不自动执行soft/cold reboot**；历史soft-reboot授权已消费。
6. 新的重启窗口须单独授权。重启后先读回KSU、双源Enforcing、注入服务、模块版本和SIM，再按v0.2.13条件决定是否需要显式refresh，最后验证LabNet-6G注册、关联与恢复。
7. UI scope为`com.android.settings`；Aware与并发模块涉及`android`时，需先审查对system_server的影响，不以force-stop Settings代替framework重注入验证。热点默认idle，未满足private key/readiness门禁不得启动。
8. 每项功能先做一次角色/业务/恢复最小验证，完整F01–F10、性能与稳定性按[最终测试规划](mt6639-plan/最终测试规划-20261025.md)集中执行；当前release_ready=false。

- `reconnect.key`：LabNet-6G STA 恢复，当前已配置；
- `ap.key`：实验热点口令，启动热点前必须提供；

这些文件不得进入 Git、ZIP 或日志。命令输出不得打印口令。

## 验证

ADB只读设备预检入口（适用于当次ADB执行域可用的窗口；当前跨Enforcing观察使用另行验证的直接LAN通道，不重启/重配ADB）：

```sh
/usr/bin/python3 tools/run_release_device_preflight.py \
  --adb $PWD/outputs/linux-adb-20261026/extracted/platform-tools/adb \
  --adb-port 5037 --serial YOUR_SERIAL --out NEW_DIRECTORY
```

显式普通应用SSH→KSU预检（当前仅完成离线实现；须先有另行准备且已验证的临时LAN实例与固定host key）：

```sh
/usr/bin/python3 tools/run_release_device_preflight.py \
  --ssh-command-json /absolute/private/ssh-command.json \
  --serial YOUR_SERIAL --out NEW_DIRECTORY
```

SSH配置沿用暂存工具的窄格式，不能同时传任何ADB选项。每次调用均复用真实普通应用→su→KSU、serial/boot身份门禁；为采集失败事实，预检不会要求先Enforcing，也不会替你切换SELinux。固定脚本退出1仍可收完整FAIL TSV；超时/连接或退出协议不明记为unconfirmed并停止，不自动重连/重放。只有完整24检查项、唯一合法boot、传输boot一致及脚本退出码均满足时才可能complete；这只表示当次预检通过，不抵扣F01–F10。`--previous-boot-id`可检查boot是否改变，soft reboot通常不改变boot，不能算cold boot。

“只读”指不改变无线状态；固定脚本会在私有远端任务目录写取证文件。真实runner尚未运行，临时LAN监听此前已到期，不因文档命令存在就自动重配或启动。实现/测试边界见预检SSH记录。

默认离线候选计划（不连接设备、不恢复事务、不安装）：

```sh
/usr/bin/python3 tools/stage_6g_candidate.py \
  --manifest release/mt6639-candidate-20261026.json --root .
```

完整宿主门禁入口（集中验收或相关实现改动时运行；文档/清单同步只做定点验证）：

```sh
/usr/bin/python3 tools/run_host_test_manifest.py \
  --manifest release/host-tests-20261026.json --out NEW_DIRECTORY
```

发布资产：

```sh
/usr/bin/python3 tools/audit_release_candidate.py \
  --manifest release/mt6639-candidate-20261026.json
```

## 回滚

1. 6G：先 `control.sh ... disable`；失败时保留 authority，不手工删除事务。
2. 已关闭事务后才可安装 v0.2.5 回滚 ZIP 或恢复本 boot 备份。
3. 热点：先停止并等待 `mtap0` 消失、Tethering idle，再禁用模块。
4. UI：禁用 LSPosed scope 或卸载 APK；先备份当前 APK。
5. 并发门禁：先 `dualsta_gate.sh disarm`，恢复 request/mode/selection，再移除 scope。
6. 任何异常都先保存 `/data/adb/mt6639-6g/transactions`、热点任务目录和状态快照。

# MT6639 Wi-Fi 徽标 LSPosed 载体部署

日期：2026-10-23。

## 结论

Settings 专用常驻模块已在 Xiaomi dijun、Android 17、KernelSU 3.3.1 的当前
late-load boot 中跑通：

- ZygiskNext 1.5.2 已把 Zygisk 注入当前 zygote；
- LSPosed 2.2.1 (7912) 已连接 system_server，Manager 显示“已激活”；
- 自建模块只 scope `com.android.settings`；
- Settings 连续 3 次冷启动均重新注入并安装两个目标 hook；
- 6GHz 事务下显示 `5G/6G` 和 `6G`，恢复 CN 后不显示任何 6G 徽标。

物理冷启动后的完整生命周期还没有验收。本轮使用 KernelSU `soft-reboot`
重新建立用户空间，KernelSU root 保持在线，然后完成 Zygisk/LSPosed 注入。

## Zygisk 选择

KernelSU 官方 FAQ 明确说明 KernelSU **没有内置 Zygisk**，并直接推荐
ZygiskNext：

- <https://github.com/tiann/KernelSU/blob/main/website/docs/guide/faq.md>
- <https://github.com/LSPosed/ZygiskNext>

本机选择 ZygiskNext 的原因：

1. LSPosed ZIP 自身声明 `Requires Zygisk enabled`；
2. ZygiskNext 是 KernelSU 官方文档点名的实现；
3. v1.5.2 于 2026-10-13 发布，明确修复部分系统上的应用崩溃；
4. 本机 KernelSU `versionCode=32680`、ksud 3.3.1，高于其最低要求
   `10940 / 11575`；
5. 本机仅安装 KernelSU，没有 Magisk/多 root 冲突。

ReZygisk v1.0.0 是开源替代，支持 KernelSU、Magisk 和 APatch，也关闭了
ZygiskNext 的部分检测面；但它对 Android 17/HyperOS 与这套 LSPosed
v2.2.1 的组合缺少同等实机证据。本轮因此不采用。

来源：

- <https://github.com/PerformanC/ReZygisk>
- <https://github.com/LSPosed/ZygiskNext/releases/tag/v1.5.2>


## 回滚

先禁用 UI 模块并结束 Settings：

```sh
adb shell am force-stop com.android.settings
```

在 LSPosed Manager 中关闭 `MT6639 Wi-Fi 6G badges`。这会撤销后续新
Settings 进程的注入，不修改原厂 APK。

若 LSPosed 本身异常：

```sh
adb shell su -c 'ksud module disable zygisk_lsposed'
adb shell su -c 'ksud module disable zygisksu'
adb shell su -c 'ksud soft-reboot'
```

需要完全回到安装前时，可按上述备份包恢复 `/data/adb/modules`；不要把
KernelSU 或提权链本身打包进功能模块。

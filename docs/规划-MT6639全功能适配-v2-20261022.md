## 1. 最终目标与范围

目标是让 Dijun 上 MT6639 及其配套系统栈能够兑现的 Wi-Fi、蓝牙功能逐项可用，形成默认行为可预测、按功能开关、可验证、可回滚的适配包。优先级继续为 6GHz，其次 MLO/热点/并发，再补齐高级协议和蓝牙。蓝牙在 v2 中纳入总规划，这是按用户本轮“MT6639 全部功能”扩展的范围；不因此打断 6GHz 主线。

“全部”必须落实为台账中的具体能力，包含厂商原本已支持但尚未实测的项目。默认支持的功能通过实测后保留原厂行为；有明确软件门禁的功能才增加适配。芯片宣传参数、其它产品用同一型号数字、驱动中有字段，均只能生成候选项。

硬件/固件真实不支持的项目，需记录充分证据、受限层和可选路径；这只能算完成可行性调查，不能算“全部解锁成功”。设备缺失、暂未找到接口或试验失败都不等于已经证明不支持。

本轮核心验收设备是手机 Dijun 和 XR1710G；6GHz 测试使用用户已建的独立网络，凭据不进入规划、模块默认配置或可公开报告。额外的第二客户端、支持 MLO 的 AP 配置、LE Audio 外设、广播音频收发器等，在各任务启动时核对可用性；缺少外设的项目登记待测。

基带、蜂窝频段、BL 解锁、替换 root 方案、移植其它机型 NVRAM/校准不属于本项目。

旧模块 README、旧配置注释和早期官方能力研究含过时判断，不能作为现场真相。尤其“没有 6GHz 硬件”“国家码只影响 framework”“LE Audio 属性 true 就已可用”“临时 root 不能启用”等结论不再沿用。

## 3. 状态与完成标准

每项功能记录三个互不替代的维度：

1. 能力来源：整机官方声明、本机驱动/固件、相邻平台旁证、实际协议观测。
2. 功能状态：未测、仅上报、部分通过、实测通过、受阻、有证据不支持。
3. 交付等级：记录、实验版、日用候选、已通过约定日用回归。

实验版允许质量调查尚未结束，但必须默认关闭、显式启用、有超时恢复，并列出未过项目。稳定版按具体功能晋级，不要求蓝牙或所有研究项先结束才发布 6GHz 稳定档；总项目仍保留未完事项。

“实测通过”最低需要能力暴露、协议建立、真实业务、关闭恢复四部分。需要对端参与的功能必须有对端证据。单次 ping、某个属性、某个菜单、一个 PHY 速率或 AP 的单边能力均不足以交付日用。

## 6. 适配包设计约束

共用一个功能执行核心，分别提供已有 root-only 手动入口和 KernelSU 模块入口。KSU 管理器负责生命周期和用户可见开关，功能核心不重新执行提权链。

核心接口建议为 `inspect / plan / apply <feature> / verify <feature> / restore / status / export`：

- inspect 默认只读，有界读取；plan 展示将改的配置与会断开的连接。
- apply 每次只处理明确选择的功能集，先校验身份和当前状态，记录事务，再做改动。
- verify 分别输出功能结果、业务质量、恢复状态，保留原始返回码。
- restore 只恢复本事务拥有的变更；export 导出脱敏结果和证据索引。

KSU 的 `late-load.sh`/`service.sh` 只调用共用核心，不复制另一套 WLAN 逻辑；依运行版本验证阶段时序、重复调用与卸载行为。首次 late-load 不依赖 post-fs-data/initrc；历史中 soft reboot 可触发另一流程，不能把“首次不执行”推广为永远不执行。新路径不需要通过软重启解决驱动重读。

配置与状态分开：用户的功能选择、每boot临时挂载、验收结果、原厂备份各自管理。首次安装和新 OTA 默认只检查不自动重建 Wi-Fi。启动/反复点击/重跑必须幂等；上次异常终止的事务未经恢复，不开始新的应用。

版本匹配至少包含设备/系统 fingerprint、kernel release、原厂cfg/ko SHA及所需固件版本。boot_id 用来隔离事务；不能把某次boot_id写死为永久白名单。

按需使用资源 overlay；本机6GHz/11be框架既有支持时不引入冗余APK或metamodule。需要覆盖 /system 时才单列依赖，并对真实资源结果验收。AndroPlus 无明确授权的脚本/APK不打包分发。

国家码和信道条件放进可审阅测试配置，模块不盲写全局地区属性，不默认清除 disabled/no_ir 或修改功率/校准。已有 US 实验结果是特定配置的证据，不是所有场景的默认值或“最完整驱动”。

## 7. 试验、备份与恢复

每次有风险的变更前：手机和 Mac 分别保存本次涉及的原始文件/状态，核对哈希、boot、版本及两份备份一致；有可用 USB 恢复通道后才开始切网。AP 试验前单独备份受影响配置，保留其余网络。

记录边界：Wi-Fi on/off、扫描设置、国家码 override、实际 driver country、挂载命名空间、保存网络集合、选中网络、地址/路由、相关属性与接口角色。保存网络与对端选择以现状为基准，不删除别人新增的项目，也不把凭据收进普通日志。

执行状态为 `检查 → 备份 → 应用 → 重建 → 验证 → 恢复 → 验证恢复`。错误、用户取消、超时、设备重启各有终态。trap只能处理部分退出；SIGKILL/掉线还需要独立看护或下次启动的未完成事务识别。看护进程如何获得权限、存活及完成恢复须实测，不能仅凭存在一个 watchdog 文件就登记通过。

恢复分层：先解除本事务覆盖并恢复设置，正常重建Wi-Fi，等待接口/关联/路由/IP稳定，再绑定正确WLAN接口做连通复核。L3超时单独报失败，不能误用蜂窝/VPN源地址。后续新复核成功写新结果，不重写原自动恢复失败记录。

ADB不可达、boot变化、AP重启、其它任务在操作网络、版本不符、备份不一致或出现新的系统级异常时，结束当前实验批次并保存证据。需要整机重启时必须与手机使用及其它任务排期协调；恢复不应被一个无限等待掩盖。

## 8. 质量门槛与试验预算

以下是初始验收目标，需在第一批性能基线后固定为具体测试配置；它们不代表目前已经通过，也不保证没有低概率缺陷。

| 层级 | 初始目标 |
| --- | --- |
| 可用性 | 同一明确配置至少3次独立关联、每次100个ICMP，重复包0，受控近距目标丢包0；任何失败保留，不用“重试成功”抹去 |
| 业务 | 上/下行TCP各3轮60秒、独立UDP速率台阶；记录吞吐、延迟分位、抖动、丢包、重传增量及温度；无线PHY不作为吞吐门槛 |
| 对照 | 固定位置、对端、版本与负载；比较原厂5GHz及实验6GHz；160/320或EHT/HE只在单变量可控时比较 |
| 重连 | 对应功能10次正常Wi-Fi关开、睡眠/唤醒后链路与业务恢复；记录耗时与失败 |
| 生命周期 | 实验入口首次/重复执行、取消、超时、禁用、卸载、重启后无root/恢复root等分别演示；完整重启项另行安排至少3个boot |
| 日用候选 | 每个准备交付的档位完成至少24小时混合使用观察，包含音频共存、休眠和充电；异常保持阻塞或降级 |

iperf3 对端 CPU、AP datapath、网络接口速率必须记录；若测试链路被以太网/CPU限制，不把结果当手机射频上限。不同设备时钟未同步时，优先按包标识和各端相对时间分析，不直接相减得空口时延。

普通 wlan0/AP接口数据抓包不能观察802.11 Retry位；空口重试需要monitor/radiotap等另一类证据。MAC重传计数、IP重复、应用丢包必须分别统计。

高级特性必须用能触发它的AP/客户端和负载；无法触发就保留未测。例如没有MU业务或相应捕获，不根据EHT能力位宣称MRU已经使用。

## 9. 协作与交付顺序

本窗口串行操作手机/AP并维护事务；其它代理可只读分析日志、源码、协议和离线工具。按任务分配文件所有权，任何代理不以独立研究任务操作设备。

模型选择在执行时核对可调用目录，沿用用户有额度的指定通道；不再默认使用 默认模型。派活使用任务文件通道，回收终态与产物后再结束本批次。这个规划没有新派代理。

第一批交付：T01 基线报告、T02有界恢复演示、T03有效6GHz双端包证据及可重复结果；T05可同时做默认关闭的实验开关。该批结束后再按证据决定T04的单变量对照与MLO/热点任务次序。

后续每批交付四样东西：改动清单、验证命令/数据和真实结论、已知限制与恢复办法、更新后的能力台账。按档位发布，不用一个“全部已解锁”总开关掩盖各项差异。

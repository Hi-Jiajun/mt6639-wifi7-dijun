# T02B 进程与 WAL 骨架实施计划

> 执行方式：本窗口在当前已隔离的独立仓库功能分支逐项实施，测试先行。沿用已批准总规划，不另外新建 worktree 或更改 root 工具。

**目标：** 实现后续真实 WLAN 事务所需的持久日志、单修改者、异常退出接管底座，并在手机任务目录演示；夹具通过不是 T02 或全功能适配通过。

**架构：** 原生用户态 C 看护进程持有事务锁，fork 一个只调用内置文件操作、不 fork/exec 的修改进程。修改者独立持有操作锁；看护者取消或超时后，先 waitpid 确认直属修改者退出，再非阻塞取得操作锁、重新读日志及对象，恢复仍属于事务的夹具。不执行任意 shell 或接受 WLAN 路径。

**技术栈：** macOS clang + Python unittest，Android 已有 Termux tcc + Bionic。不安装 NDK，不加载 LKM。

**规格：** [总规划](../规划-MT6639全功能适配-v2-20261022.md)、任务分解 T02、[T02A 所有权规则](T02A-恢复判定器-20261023.md)。

## 全局边界

- 不改 wifi.cfg、国家码、扫描设置、保存网络、AP、root/BL/SELinux。
- 新建事务目录必须属于当前有效 UID、0700，目录与各固定名称文件禁止符号链接，禁止复用已有事务。
- 修改和恢复均先写意图并 fsync，终态只在资源复核后写入；文件新增和日志创建也 fsync 目录。
- 日志破损、未知外部内容或身份不符均 blocked；不删除证据，不以 baseline 文件碰巧相同取代事务关闭。
- PID 信号只发给看护者尚未 reap 的直属子进程；不是父子关系的恢复入口不做检查 starttime 后再 kill 的竞态操作。
- 本批支持看护者存活时的修改进程死亡；看护者被杀后只能锁空闲后保守恢复，活的旧修改者不自动强杀。后续 Linux pidfd 围栏/独立租约仍须补齐。
- 跨 boot、真实挂载、系统设置、ADB 断开独立存活、root 丢失及重启路径均未因此验收。

## 文件与接口

- `native/recovery/probe.c`：`probe-run DIR HOLD_MS DEADLINE_MS [STAGE]` 和 `probe-recover DIR`，仅操作 DIR 内固定 fixture/日志文件；STAGE 为 before/intent/effect/applied/restored 的诊断停留点。
- `native/recovery/abi.h`：主机标准 POSIX 头；Android AArch64 缺系统头环境下的最小 Bionic ABI 声明。只适用 LP64 AArch64。
- `tests/test_recovery_probe.py`：真实编译并启动进程，检查实际文件、退出码、锁竞争、取消、kill、外部冲突和损坏日志；不模拟锁或进程。
- `docs/验证-T02B进程骨架-20261023.md`：本批实际命令、失败/通过与下一安全门。

stdout 是 JSONL 事件；终态字段分别为 `operation` 和 `recovery`。0=夹具终态成功（`restored` 或 T02C 的 `not_applied`），2=事务忙，3=所有权/证据冲突，4=I/O或不能证明修改者退出，64=参数错误。`cancelled/not_applied` 表示在 before 授权门前取消，没有启动修改者；消费者必须解析 JSON 的两个字段，不能仅凭 ready 或退出0宣布已应用或 WLAN 恢复。

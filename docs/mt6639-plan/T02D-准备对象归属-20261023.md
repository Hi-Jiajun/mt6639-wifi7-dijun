# T02D prepared-object identity Implementation Plan

> 本窗口沿用已批准功能分支实施并收齐独立复审，测试先行；不另建工作树、不自动合并。

**Goal:** 在现有持锁/修改者进程中验证一种在 intent 崩溃窗口仍可核验归属的对象协议，为真实覆盖资源适配提供前置证据。

**Architecture:** 新增 `probe-exchange-run DIR HOLD DEADLINE [STAGE]` / `probe-exchange-recover DIR`。保留旧 probe_v1 行为；新日志环境头为 probe_exchange_v1，不跨适配器恢复。准备两个私有普通文件 fixture=baseline、prepared=candidate，操作前持久化两份独立 dev/ino 记录。worker 在 intent 后原子交换两个名字；恢复仅在两个对象身份、内容、模式与记录完全符合原位或互换状态时运行。原始对象始终保留；操作不重新写入内容，不凭 candidate 摘要认领异物。

**Tech Stack:** POSIX C；Linux renameat2(RENAME_EXCHANGE)、macOS renameatx_np(RENAME_SWAP)，Android 静态 ARM64/musl 先验证，Bionic/root 路径独立保留未验收。

**Spec:** [已批准总规划](../规划-MT6639全功能适配-v2-20261022.md)第7节；任务分解 T02；[T02A](T02A-恢复判定器-20261023.md)禁止摘要冒认；T02C。

## 全局约束

仅操作用户提供的私有任务目录内固定名字；不访问 WLAN/AP/root 链，不删除对象。无外部替换时本程序保留两端原对象；若外部写者先替换或删除对象，不承诺追回。互斥、before 授权门、waitpid 后恢复、boot/ns、目录及文件权限沿用已验行为。不同适配器日志不兼容、不猜测。强身份指两份事前登记对象的精确配对，不表示能防御任意恶意同 UID 修改者伪造整份 WAL。检查与交换间的外部写者竞态仍需独占窗口与后续 mount/进程围栏，不能冒充已解决。

真实 bind mount 的归属还需独立适配（如可事前登记 ID 的 detached mount），不能把文件交换等同于 WLAN 挂载；系统 setting、独立 ADB 租约、pidfd 和跨 boot 均继续未过门。

## 文件及可验收步骤

- 修改 `native/recovery/probe.c`：命令选择、隔离环境头、准备两对象、配对核对与恢复；旧命令默认行为不变。
- 新增 `native/recovery/exchange.h`：只提供固定两个名字的原子交换及目录 fsync，无任意路径/命令入口。
- 新增 `tests/test_prepared_recovery.py`：真实进程和 inode，不 mock rename；每项使用新700目录。
- 更新 README、任务分解、能力台账和本批验证记录；原始日志只放 local/。

- [x] 写失败测试并实际看到旧程序拒绝新命令：正常保留原 inode、effect/intent 取消、同字节异物、另一端缺失/硬链接、适配器不匹配、重复运行、setup 部分对象、closed 后漂移。
- [x] 实现 `prepared_pair()`：原位只接受 fixture=原始 inode/内容 + prepared=事前准备 inode/内容；互换只接受相反配对。必需的两份记录也必须私有普通单链接文件。

- [ ] 手机新任务目录内复验正常、effect 窗口取消、异物保留、原 inode 回归，并核对前后 stock/boot/ns/WiFi、双端二进制摘要及原始证据回拉。
- [ ] 精确文件检查、功能分支提交/私有推送；T02 总门继续关闭。

主机实现先保存功能分支检查点，不以检查点提交勾掉手机验收项；本片整体尚未完成。详见验证记录。

入口示例：`probe probe-exchange-run /absolute/private/fixture 1000 3000 effect`。测试观察到 stage=effect 后向本测试直接创建的 supervisor 发 SIGTERM；其 waitpid 后应输出 cancelled/restored、fixture 恢复原 inode、WAL 没有 applied 但闭合。若将同字节新 inode 覆盖任一端，必须 blocked 且异物保留。这两种结果是本片核心区别。

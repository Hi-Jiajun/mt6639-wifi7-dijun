# T02A：离线恢复判定器实施计划

> 执行方式：测试先行，独立复核后再合并；本切片由本窗口实现、独立复核；不操作手机。

**Goal:** 将 T02 的恢复前置条件和所有权冲突转成可运行、可测试的只读判定，避免缺证据时给出可恢复结论。

**Architecture:** Python 标准库读取独立的事务日志和观察快照，只输出建议；无 ADB、shell、设备写入或信号调用。它不是 WAL 写入器、锁实现、看门狗或恢复执行器，任何输出都不授予执行权限。

**Tech Stack:** Python 3、unittest、合成 JSON fixture。

**Spec:** [已批准规划](../规划-MT6639全功能适配-v2-20261022.md)第 6–8 节、T02。本切片仅实现其中离线判定，不完成整个 T02。

## 约束及接口

不改变 root、BL、驱动、NVRAM、AP 或手机网络。继续使用独立仓库；原始日志和凭据不提交。不能将历史采集摘要直接视为原子快照。

新增 `tools/plan_mt6639_recovery.py` 和 `tests/test_plan_mt6639_recovery.py`；更新 README 和任务分解的进度说明。CLI 为：

```sh
python3 tools/plan_mt6639_recovery.py --journal /path/journal.json --snapshot /path/snapshot.json
```

正常判定输出 `status=clean / restore_required / blocked`，退出码分别为 0 / 2 / 3；格式或文件错误退出 64，所有判定 JSON 的 `execution_authorized` 固定为 false。**所有非零退出都必须停止后续应用，不得把 64 当成可以忽略的工具错误。** 输出只含事务 ID、资源 ID 和固定原因码，不回显设置值、路径原文、进程明细或输入异常内容。标准 `--help` 是人类使用的例外：退出0并输出帮助文本；消费者必须解析和验证顶层 JSON/status，不能只凭 rc0 当 clean。

### 日志 v1

根字段：`schema=1`、`transaction`（1–64 位字母数字及 `._-`）、`phase=open|closed`、`boot_id`、`mount_namespace`、`owner={pid,starttime}`、`children=[{pid,starttime}]`、`operations`。PID 为正整数、starttime 为规范十进制字符串（除单个 `0` 外无前导零）；不接受 bool 充当数字。owner 的 PID 不得出现在 children，children 内部及 snapshot.processes 内部不得重复 PID（包括同 PID 的不同 starttime），否则输入无效。operations 必须非空，最多 128 项。

`closed` 只能由未来执行器完成全部恢复复核后写入，且全部 operation 必须 `state=restored`；本工具不会代写终态，也不会用自己返回的 clean 作为写 closed 的前提。open 日志即使全部资源已是 before，也只返回 blocked / JOURNAL_OPEN，需由执行器补齐业务及恢复验证再关闭。closed 字段是调用者的证据声明，不代表本层验证过其真实性。

boot/namespace 作为非空、无控制字符、最长4096字符的不透明字符串，逐字符严格相等，禁止数字提取、前缀匹配或归一化。真实值例为 UUID 格式 boot 和 `mnt:[4026531840]`；离线 fixture 可用合成值。

每项 operation：`id`、`kind=setting|mount`、`state=intent|applied|restored`、`before`、`after`。ID 不重复，setting 的 ID 仅为 `wifi_enabled / scan_always_enabled / country_override`，before/after 为字符串；开关仅取字符串 `"0"/"1"`，country 为字符串 `"null"`（明确读到无 override）或两个大写字母。setting 中 **JSON null 永远表示无效/缺证据**，不能表示无 override，和 T01 的字符串/缺失语义保持一致。before/after 对两种 kind 均必须不同。

mount 的 ID 固定为 `wifi_cfg`；before/after 包含 `mount_id`（正整数）、`major_minor`、`root`、`mount_point`、`stat_dev`、`stat_ino`、`sha256`。这是完整挂载记录与文件身份，不是单独内容哈希。before 的 mount_point 必须是目标的祖先而非目标自身（既有精确目标挂载应被前置门拒绝）；after 的 mount_point 必须是目标本身，mount_id 必须是新 ID。`after` 在 `intent` 阶段允许 JSON null：若挂载后未记录实际身份，不猜 mount_id；当前不是 before 时必须 blocked。applied 必须有完整 after。经执行器核实从未应用、恢复复核后标记 restored 的条目可保留 after=null，不得为关闭零副作用事务伪造挂载身份；这种条目也只接受当前完整 before，否则 blocked。不能把同内容但不同 inode/mount 的对象当成自己挂的。

mount 的 major_minor 为规范十进制 `主:次` 字符串；stat_dev/stat_ino 为规范十进制字符串，inode 不得为0；sha256 为64位小写十六进制；root/mount_point 为非空、无控制字符的绝对路径字符串。before 必须指向存在的原厂文件及其覆盖挂载，目标缺失不在本切片支持范围。日志固定对象和快照顶层严格校验字段集合；不接受额外字段、JSON 重复键、NaN/Infinity、超2MiB输入或非普通文件。resource 条目或其观测值形状无效则作为证据不足返回3，不视为有效值。

日志是调用者提供的证据，不在此层保证 fsync 或真实性；未来写入器必须 WAL 先行，本工具不把一个 JSON 文件当成持久化或互斥证明。

### 快照 v1

根字段：`schema=1`、`transaction`、`boot_id_before / boot_id_after`、`mount_namespace_before / mount_namespace_after`、`exclusive_window`、`lock_acquired`、`process_inventory_complete`、`processes=[{pid,starttime}]`、`resources`。

三个布尔前置条件必须显式 true；它们须来自未来执行器实际观测，不能由当前采集器默认补值。日志和快照 schema 都必须是整数1，transaction 必须逐字符相同，否则格式拒绝或 TRANSACTION_MISMATCH。快照两端 boot/namespace 必须相同且等于日志。跨 boot 一律 blocked；不能因临时 mount 消失就宣布持久设置恢复。

processes 为完整观测中的当前进程身份。owner 或任何 children 同 PID、同 starttime 仍存活时 blocked；同 PID 不同 starttime 只表示旧身份已消失，不发送信号、不终止新进程。完整 inventory 的获取及后续不再生子进程的证明尚属执行器验收内容。未记录的子孙进程不在本层防护范围；未来执行器必须通过会话/cgroup或等效机制收束并证明 quiescence，不能仅凭匹配PID已消失声称进程围栏通过。

resources 必须恰好覆盖 operation ID，额外 ID 返回 UNEXPECTED_RESOURCE，重复 JSON 键拒绝为64。每项 `{status, value}` 的 status 必须为 `ok` 才能使用 value；缺失、失败或未知一律 blocked，不把 JSON null/空输出当 baseline；字符串 `"null"` 仅在 country_override 上是有效值。

## 判定规则

全局前置条件不满足：blocked。满足后按每个资源独立比较，最终有任何 blocked 则总状态 blocked；没有 blocked 但有 restore 则 restore_required，否则 clean。

| 当前值 | 日志状态 | 结果 |
| --- | --- | --- |
| 等于 before 完整身份/值 | 任意 | already_baseline，不重复恢复；若全部资源如此但 phase=open，总状态仍 blocked / JOURNAL_OPEN |
| 等于完整 after | applied | restore_required 的建议；不执行 |
| 不等于 before（包括等于 after） | intent | blocked：意图不能证明已经应用、也不能证明所有权 |
| 等于 after 或其它值 | restored | blocked：外部或不一致状态，不覆盖 |
| 不等于 before，且 mount after 未记录 | intent | blocked：无法证明挂载所有权 |
| 其它值/不完整/探针非 ok | 任意 | blocked：冲突或证据不足 |

按表格自上而下求值。即便 setting 当前等于已确认应用的 after，也不能证明没有外部写者做过相同修改。`exclusive_window` 是受控实验前置约定而非 CAS；报告只是即时建议，不可跨时间缓存后执行。未来执行器在持锁和 quiescence 期间重新核对每项状态。

closed 日志的外部漂移也保守返回 blocked，不建议覆写；它仅表示“当前状态和这份历史证据不匹配”，不反推原恢复失败。clean 仅指已声明关闭的日志中**已记录资源**目前匹配 before，不是 T02 业务验收，不能作为开始新试验的独立授权。

### 输出及错误分类

单个 JSON 判定输出：`{schema:1, transaction, status, execution_authorized:false, reasons:[], resources:[{id,decision,reason}]}`。resources 按日志中的操作顺序排列。格式错误输出省略 transaction，status=invalid_input，固定原因 INVALID_INPUT。文件/语法/日志或快照顶层字段集合/类型/枚举错误（包括 applied 缺 after、空 operations、closed 却未 restored）为64；resource 条目字段/值形状无效、证据冲突/不足为3。二者都必须阻止后续应用。

固定全局原因码：TRANSACTION_MISMATCH、BOOT_CHANGED、MOUNT_NAMESPACE_CHANGED、EXCLUSIVE_WINDOW_REQUIRED、LOCK_REQUIRED、PROCESS_INVENTORY_INCOMPLETE、OWNED_PROCESS_ALIVE、UNEXPECTED_RESOURCE、RESOURCE_BLOCKED、JOURNAL_OPEN。固定资源原因码：EVIDENCE_UNAVAILABLE、BASELINE_MATCH、RESTORED_RECORD_CONFLICT、OWNERSHIP_UNCONFIRMED、AFTER_MATCH、EXTERNAL_CONFLICT。全局前置门不过时 resources 留空，不给部分恢复建议；资源级 conflict 时仍列各资源观察，但总状态 blocked、禁止据其中建议执行。

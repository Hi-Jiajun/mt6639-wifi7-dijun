# 适配范围：手机终端适用

日期：2026-10-28。用户确认：MT6639 全功能适配以**手机终端所需**为准，其它非手机终端场景（CPE、路由器、专业 AP 形态）不需要适配。本文件是范围基线，优先于旧文档里"把热点当 AP 产品来验收"的隐含口径。

## 范围内：要达标

| 域 | 手机终端用例 | 对应验收项 |
| --- | --- | --- |
| STA 上网 | 2.4/5/6GHz 关联、11be、320MHz、puncturing 接收、重连/休眠/漫游 | F02、F03、F05 |
| 手机热点 | 2.4/5/6GHz SoftAP 起停、单客户端真实关联 + DHCP + 过流量 + 关闭恢复 | F07 |
| 投屏与直连 | 手机端 P2P 角色、Miracast 投屏（对端具备时） | F06 |
| 蓝牙 | A2DP/HFP/BLE 日用路径 + LE Audio Host/Controller 能力开放 | F08 |
| 系统与模块 | KernelSU 越狱模式、模块启禁卸载、6G 标识 UI、重启自愈 | F01、F02、F10 |
| 可选诊断 | RTT/FTM、NAN 仅在本机能力实际存在时 | F09 |

## 范围外：不要求

| 场景 | 不做的理由 |
| --- | --- |
| 手机当打孔 AP | 需要补 `NL80211_EXT_FEATURE_PUNCT`、改原厂 ko 并经 MCU PP 提交，属 AP 设备能力 |
| 多客户端 AP 压测、企业级 AP 特性 | 手机热点日常只需少量客户端，不追求 AP 级调度与容量 |
| 320MHz 热点对外协商的极限吞吐 | 受对端网卡制约（桌面 MT7922 仅 11ax 2x2），也不是手机侧能力 |
| CPE / 路由器 / mesh 角色 | 非手机终端形态 |
| monitor 模式、帧注入、抓包设备化 | 属诊断设备用途，风险与收益不匹配 |
| 5+6GHz MLO | 原厂驱动白名单禁止、2x2 射频限制；用户已决定不深入 |
| 完整 LE Audio 外设全角色认证 | 当前只有 AirPods Pro 3，只做 Host 侧开放与回读 |

## 对验收口径的影响

- **F06 整组挂起**：secondary CMM、P2P GC、Miracast 实投暂不做；既有证据保留，不计入完成度，有第二对端时再启。
- **F07 降级为"手机热点可用"**：单客户端关联/DHCP/吞吐已是判据；多客户端、320MHz 真实协商、IPv6/offload 记为范围外可选，不再作为晋级前提。
- **F09 最低优先级**：NAN/Aware 属可选邻近发现，不影响手机上网主路径；RTT/FTM 本机 bitmap=0 属厂商未开放。
- **对端限制单独计数**：因 AP 固件或对端网卡缺失而无法测的项记为 blocked-by-peer，不算手机侧缺陷，也不阻止其它项晋级。
- **不豁免的项**：cold boot 自动可用、模块启禁卸载、3 boot/24 小时稳定、原厂 5GHz 回归仍是范围内硬要求。

## 3. 过度结论与修正

1. **“没有 6GHz 硬件”**（`modules/mt6639-full/config.conf` 的 `ENABLE_6G` 注释；`local/6g-test/README.md:52` “大概率没有 FEM/天线”）——没有足够证据。修正：设备记录给出 qm45197 FEM，但具体频段还缺可核验数据表；完整射频链与收发未知。`RESULTS-20261022.md:74` 与其 §10 自相矛盾，不能将后者也未经核实当成最终证明。
2. **“STA 没有提升空间 / 已满”**（`README.md:9,16`）——只记录了当前 AP 下 5GHz EHT 协商 2882Mbps；MLO、6GHz、320MHz、实际吞吐未测。修正：已有单连接 EHT 证据，其余独立验收。
3. **“HAL 已确定唯一门禁”**（`README.md:10,93`；`RESULTS-20261022.md:108`）——现有证据只排除“Android 框架 → SoftApManager → AIDL hostapd”路径；因无独立 hostapd，驱动/固件 AP EHT 能力未直测。修正：HAL/hostapd 是已证实受阻层，非唯一门禁。
4. **“LE Audio 可开”**（`README.md:14`）——属性置 true ≠ 协议可用；验收需兼容外设的真实协议/音频会话，offload 是否启用单独验证。

默认方案（纯只读）：完整重启进入原厂态后，① 记录 boot_id 与 dmesg 中 wlan 驱动 probe 段；② 若能读 `/proc/kallsyms`，比对 `wlanProbe` 符号偏移与离线反汇编是否一致（验证 0x14a0b0 结论，不写内存）；③ 跑原厂 `iw phy` 与 `cmd wifi get-allowed-channel -b 8` 作为 6GHz 空列表基准。全程不写 capability、不改指令。

本机当前没有注册 6GHz 频段，不把“原厂看不到 6GHz AP”当作额外硬件否定证据。6GHz 对端先用于验证测试环境，等本机频段及信道条件成立后再做扫描实验。

## 7. 结论

原始快照已证实：5GHz EHT 协商 2882Mbps、phy 仅 Band 1/2、AP 6G 列表空。已有记录还给出 rmmod 未成功、refcnt=2、FEM 为 qm45197；具体 errno 和 FEM 原始输出应补归档。

需修正：三个过度结论（无 6GHz 硬件 / STA 无提升空间 / HAL 唯一门禁）。

原型缺口：wlan6g LKM 不可卸载、失败被掩、KCFI/CRC/偏移未运行时验证；设备当前处于非恢复态，一切高危实验须先过 G0。

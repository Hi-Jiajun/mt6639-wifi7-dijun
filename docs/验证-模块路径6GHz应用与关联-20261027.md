# 模块路径 6GHz 应用与关联（2026-10-27 15:43–15:52）

这是本项目中**第一次用 v0.2.13 模块（而不是手动改国家码）**把 6GHz 打开并跑通真实流量。

## 动作序列

1. `cmd wifi set-wifi-enabled enabled` → 连回 LabNet-5G；`apply.log` **没有**因 Wi‑Fi 开启而自动补跑（最后一条仍是 15:10 的 skip）。
2. `su -c sh /data/adb/modules/mt6639-6g/bin/control.sh <moddir> enable` → rc=0：
   - `native old-boot authority retired (not recovered) tx=t-<BOOT_ID>-…`（旧 boot 遗留 authority 被作废）
   - `native transaction active tx=t-<BOOT_ID>-<TS>-XXXXXX guardian=30617`
   - 返回 `{"status":"active","guardian_pid":30617}`
3. 复读：`/proc/mounts` 中 `wifi.cfg` 计数 **1**（cfg 已接管），`state=active`。
4. `wifi off → 4s → on → 14s` 后复读 `iw phy`：
   - `6135.0 MHz [37] (0.0 dBm)` 出现
   - 全 phy `disabled` 计数 60 → **5**
   - `cmd wifi get-country-code` = **US**（模块事务自行设置，非手动 override）
5. 扫描：`LabNet-6G` 可见（另见同 SSID 的 `6295MHz` BSSID，AP 侧另有信道）。
6. `cmd wifi connect-network LabNet-6G wpa3 <口令>` → **关联成功**：
   - `iw dev wlan0 link`：SSID LabNet-6G，**freq 6135.0**，signal −46dBm
7. 连通性与数据面：
   - `ping 198.51.100.242`（AP）5/5，0% 丢包，但**出现 +14 duplicates**
   - `ping 198.51.100.60` 3/3
   - `toybox nc` 拉 `.60:8989` 100MB：**0.927s**（≈906Mbps 量级，粗测）

## 结论与边界

- **W02 从"手动国家码路径"升级为"模块路径"**：注册、关联、数据面三项都由 v0.2.13 事务完成，未使用 `force-country-code`。
- 模块在 `control.sh enable` 时把 country 置为 US（复读确认），这说明"开机自动 6G"的实现落点确实在模块事务里，而不是框架设置键——与源码核实的推断方向一致，但仍需跨 boot 验证开机是否自动应用（本次是手动 `enable` 触发的）。
- `+14 duplicates` 与 F03 历史现象一致，属**已复现、未定位**，不记为通过。
- 100MB 粗测仍受 `nc|wc` 与省电策略影响，不作吞吐下限或性能验收（F04 仍未做正式轮次）。
- 本次未跑 `refresh`、未改 SELinux、未重启；设备停留在 6GHz 已连接状态。

# 打孔 A/B 吞吐对照：ON 比 OFF 低 20%，量级与"少用 80MHz"吻合（2026-10-27）

## 结论

1. **手机作为 STA 能跟随打孔 AP 正常工作**：两台 AP 开启打孔后都能关联到 320MHz、双向跑数据，没有出现关联失败或退回 160MHz。
2. **AP-1那台给出第一条吞吐级证据**：同一 BSS、同一位置、同参数，打孔 ON 下行均值 **2.60 Gbps**，OFF **3.24 Gbps**，比值 **0.80**（理论"320MHz 只用 240MHz"为 0.75）。两组**无重叠**（ON 最高 2.74 < OFF 最低 3.19）。
3. 这仍然**不是逐 PPDU 证据**：没有频谱/抓包，也没有 PP 回执；结论强度是"强旁证"，不是"已证明射频按位图避让"。
4. AP-2那台**判不了**：手机离它 −75 dBm，ON/OFF 都是 0.26/0.27 Gbps，弱信号把带宽差异压掉了。

## 方法

- 采集工具：`tools/punct_ab_probe.py`（固定 BSSID 关联 → link/station dump/扫描里的 EHT Operation → ping 20 包 → iperf3 双向 → dmesg 增量）。
- 服务端：内网 `198.51.100.60:5201`（临时启动，测完关闭）。客户端：手机 `/system/bin/iperf3`，4 条 TCP 流 × 6 s。
- 对照组切换由 AP 协作会话执行：`uci set wireless.radio2.hostapd_options` + `wifi reload`（约 30 s，不重启、不换模块）。
- 手机位置固定（AP-1 旁，−43~−44 dBm），全程未改国家码、未重启、未动模块。

## 数据

### AP-1 `02:00:00:00:73:1c`（6135 MHz，320MHz，`punct_bitmap=0x000f`）

| 状态 | IE 读数 | 下行 Gbps（逐次） | 均值 | 上行 Gbps |
| --- | --- | --- | --- | --- |
| ON | `params=0x43`，`bitmap=0x0f00`，ccfs0=47/ccfs1=31 | 2.72 / 2.66 / 2.74 / 2.25 | **2.60** | 1.40 / 1.45 / 1.46 / 1.38 |
| OFF | `params=0x41`，无 bitmap | 3.34 / 3.19 / 3.20 | **3.24** | 1.42 / 1.42 / 1.44 |

- ON/OFF 下行比 **0.80**；两组区间不重叠。
- 上行两边都是 ~1.40–1.46，**没有变化** —— 上行被手机发射功率/省电卡住，不是带宽受限，不能用来判打孔。
- 关联状态两边都是 320MHz、`rx/tx bitrate 5764.8`。这是按 chandef 算的名义值，两种状态完全一样，**不能当判据**。

### AP-2 `02:00:00:00:77:7c`（6295 MHz，320MHz，`punct_bitmap=0xf000`）

| 状态 | 下行 | 上行 |
| --- | --- | --- |
| ON（`params=0x43`，`bitmap=0x00f0`） | 0.264 Gbps | 0.270 Gbps |
| OFF（16:45 基线，`params=0x41`） | 0.259 Gbps | 0.300 Gbps |

手机在这里只有 −75 dBm，两种状态速率都被弱信号压在 0.26–0.30，**没有区分力**。要用它做对照，得把手机移到 AP 附近重测。

## 过程中的两条观察

1. **一次性的 SAE 发送失败**：首次固定 BSSID 连AP-1时，驱动报
   `aisFsmRunEventMgmtFrameTxDone:(AIS ERROR) Mgmt Frame TX Fail, Status:3.`，
   紧接着重试即成功，之后 7 次关联都正常。按"偶发"记录，不归因于打孔。
2. **同名 SSID 的分支**：两台 AP 共用 `LabNet-6G`，`cmd wifi connect-network … -b <bssid>` 在已连到同名 SSID 的另一条 BSS 时会被当成 no-op；要先 `forget-network` 或回落其它 SSID 后重连才会重新钉 BSSID。工具里已按这个事实处理。

## 边界

- AP 侧驱动/固件是否真的把 80MHz 关掉，仍缺频谱或 PP 回执；本条只证明"端到端吞吐随位图状态变化，且变化量级与带宽缺失一致"。
- 每次 `wifi reload` 会把客户端踢下线（手机自动回落 5G 后重连），属预期行为。
- 单点位、单方向多轮，未做多点位；未做 2.4/5G 影响评估。

# F07 外部客户端接手机 6GHz 热点（首次真机）

日期：2026-10-27 22:20–22:45。范围：用桌面 MT7922 当外部客户端，关联手机 `mt6639-hotspot` 起的 6GHz 原生热点，验证关联、DHCP、ICMP 与一次吞吐。**单个客户端、单次运行**，不是 F07 的完整验收。

## 先修好客户端这一侧（桌面）

桌面一直扫不到任何 6GHz，根因不在手机：

```text
cfg80211: Direct firmware load for regulatory.db failed with error -2
cfg80211: failed to load regulatory.db
```

宿主没装 `wireless-regdb`，cfg80211 只能停在 `country 00`，6GHz 频道全部 `(disabled)`。处理：装 `wireless-regdb`，卸载并重载 `mt7921e / mt76 / mac80211 / cfg80211` 链，再 `iw reg set US`。结果：

- `iw reg get` → `country US: DFS-FCC`
- 6GHz 频道出现且可用（例：`6015.0 MHz [13] (12.0 dBm) (no IR)`，共 29 个条目）
- `iw dev wlp6s0 scan dump` 能读到手机的 `02:00:00:00:0a:00 freq: 6135.0`

另外把 `iw`、`dhcpcd`、`iperf3` 装上；Wi-Fi 全程没进默认路由（DHCP 用 `dhcpcd -G`，默认路由始终是 `<HOST_IFACE>`）。

## 手机侧起 6G 热点

当前空口里可见的 LabNet-6G 在 6295MHz（`02:00:00:00:77:7c`），不是 runner 写死的 `6135 / 02:00:00:00:73:1c`，所以 `auto` 判定为 `wifi` 后失败：

```text
REJECT runner_exited_during_start reason=sta_upstream_mismatch
```

改用 `MT6639_HOTSPOT_UPSTREAM=wifi-any`（STA 已连在某个 6GHz 网络上，上游走 wlan0，但不钉死 BSSID）后正常：

```text
state=active task=/data/local/tmp/mt6639-native-ap-3f209235-86400-hQl4er pid=31775 band=6g width=20 hold=86400
mtap0: inet 203.0.113.174/24
ssid MT6639-Native-6g-20 / channel=37 (6135)
```

## 客户端关联与业务

AP 是 `wpa_key_mgmt=SAE`、`ieee80211w=2`、`sae_pwe=1`，因此客户端配置必须同样是 SAE + PMF：

```text
wlp6s0: SME: Trying to authenticate with 02:00:00:00:0a:00 (SSID='MT6639-Native-6g-20' freq=6135 MHz)
wlp6s0: CTRL-EVENT-CONNECTED
Connected to 02:00:00:00:0a:00
	SSID: MT6639-Native-6g-20  freq: 6135.0  signal: -41 dBm
```

| 项目 | 结果 |
| --- | --- |
| 关联 | 6135MHz、SAE、PMF、−41 dBm，BSSID 就是手机 `mtap0` |
| DHCP | 客户端拿到 `203.0.113.157/24 dynamic`；手机侧邻居表出现 `203.0.113.157 lladdr 02:00:00:00:c7:f9` |
| IPv6 | 手机邻居表有 `fe80::…` 链路本地项；AP 没有全局前缀，SLAAC 只到链路本地 |
| ICMP | 到 AP `203.0.113.174` 4/4，0% 丢包，avg 15.0ms |
| 吞吐 | iperf3 4 流、手机→桌面 6 秒：receiver 632 Mbps（sender 693 Mbps） |

## 一个没解释清的运行态不一致

AP 配置是 20MHz（`op_class=131`、`channel=37`、`he_oper_chwidth=0`、`eht_oper_chwidth=0`），但客户端实际链路是：

```text
tx bitrate: 2161.3 MBit/s 160MHz HE-MCS 10 HE-NSS 2
rx bitrate:  864.6 MBit/s 160MHz HE-MCS 4  HE-NSS 2
```

即"请求 20MHz、实跑 160MHz"，与 5GHz 那次"驱动把 80MHz 挪到 6135/320MHz"是同一类现象。本轮**没有**定位是 beacon 的 EHT Operation 语义、驱动覆盖还是客户端取值口径，先按未解释的观察记录，不作为 20MHz 生效的证据，也不据此改模块。另外客户端是 MT7922（11ax 2x2），本来只能到 HE，协商结果出现 HE-MCS 而不是 EHT 属预期，不能拿来判手机侧 EHT 能力。

## 收尾

- 热点：`state=idle restored=1 action_rc=0`，`mtap0` 已消失，原厂状态恢复。
- 手机 STA：停热点后自动回到 `LabNet-6G` / 6135 / `02:00:00:00:73:1c`——顺带证明AP-1那台 AP 的 6G 现在是通的（之前只看到 6295 那台是扫描缓存/另一台 AP 的问题）。
- 桌面：`dhcpcd -k`、杀掉自起的 wpa_supplicant、`wlp6s0` 置 down 并交回 NetworkManager；默认路由始终是有线。
- 桌面新增软件：`iw`、`wireless-regdb`、`dhcpcd`、`iperf3`；重载过一次 Wi-Fi 驱动模块链（Wi-Fi 当时未使用）。
- **踩坑（已修）**：`dhcpcd` 跑完会把 `/etc/resolv.conf` 改成"Generated by dhcpcd"且不含 nameserver，导致整机 DNS 失效（表现为 git 无法解析 github.com）。用 `systemctl restart NetworkManager` 让它按 DHCP 重新生成即恢复（`nameserver 223.5.5.5`）。以后在这个宿主上跑 `dhcpcd` 要带 `-C resolv.conf`（不接管 DNS），否则会顶掉 NetworkManager 的解析配置。
- **踩坑（已修）**：手工起的 `wpa_supplicant` 退出后，系统 supplicant 仍报 `wpa_supplicant couldn't grab this interface`，NetworkManager 里 `wlp6s0` 一直是 `unavailable`。`systemctl restart wpa_supplicant` 再重启 NetworkManager 后恢复为 `disconnected`，扫描重新可用（6 个 LabNet 条目）。教训：手工接管接口的实验结束后要重启系统 supplicant，而不只是杀进程。

## 边界

单客户端、单次、单个带宽档（且宽度存在上面的不一致）；没有 IPv6 转发/offload、没有 320MHz、没有多客户端并发、没有长时间稳定性。F07 仍为 partial，不能据此宣布热点验收通过。
